# 📹 TRASSIR Monitor / Трассир Монитор

> **Система мониторинга серверов TRASSIR** — веб-дашборд с live-обновлением, алертами, историей, Telegram и Email уведомлениями.

[![Platform](https://img.shields.io/badge/platform-Debian%2F12%2F13-blue)](https://www.debian.org/)
[![Python](https://img.shields.io/badge/python-3.x-blue)](https://www.python.org/)
[![Shell](https://img.shields.io/badge/install-one--liner-green)](#-быстрая-установка)

---

## 🌐 Что это такое?

**TRASSIR Monitor** (Трассир Монитор) — самостоятельно размещаемое веб-приложение для мониторинга серверов видеонаблюдения [TRASSIR](https://www.dssl.ru/).  
Устанавливается одной командой на Debian, не требует ручной настройки Python или Nginx.

### Ключевые слова для поиска
`Трассир Монитор` · `TRASSIR Monitor` · `мониторинг TRASSIR` · `TRASSIR Dashboard` · `трассир алерты` · `видеонаблюдение мониторинг linux` · `trassir telegram уведомления` · `trassir email alert` · `trassir camera offline`

## ✨ Возможности

| Функция | Описание |
|---|---|
| 🏠 Live-дашборд | Все серверы на одном экране, автообновление через WebSocket |
| 📷 Имена офлайн-камер | Определяет конкретные названия каналов через API `/objects/` TRASSIR |
| 🔔 Алерты | Диски, CPU, камеры, архив — без дублирования (1 событие = 1 алерт) |
| ✅ Восстановления | Отдельный алерт при возврате в онлайн + расчёт времени простоя |
| 📊 Графики | CPU, камеры, архив за 6 ч / 24 ч / 7 дн |
| 💬 Telegram | Мгновенные уведомления, поддержка HTTP-прокси, несколько получателей |
| 📬 Email | HTML-письма через SMTP (Gmail, Yandex, Mail.ru, корпоративный) |
| ⚙️ Веб-настройки | Управление серверами, SMTP, Telegram — через браузер на `/settings` |
| 🕐 Московское время | Все данные сохраняются в UTC+3 |
| 🗑 Деинсталлятор | Удаляет только проект, системные пакеты не трогает |

---

## 📦 Системные требования

- **ОС:** Debian 12 / 13
- **Права:** root / sudo
- **Серверы TRASSIR** с включённым веб-сервером и заполненным SDK-паролем
- Свободный порт (по умолчанию `8080`)
- Интернет на время установки

> Python 3, виртуальное окружение, Nginx и все зависимости устанавливаются **автоматически**.

## 🚀 Быстрая установка

### 0. Через единый лаунчер (рекомендуется)

Одна команда вместо трёх — интерактивное меню для установки дашборда,
уведомлений, смены пароля, обновления и удаления:

```bash
wget -O launcher-trassir-monitor.sh https://raw.githubusercontent.com/scp-oss/TRASSIR-Monitor/main/launcher-trassir-monitor.sh
sudo bash launcher-trassir-monitor.sh
```

> ⚠️ Всегда используйте `-O <имя>` при повторном скачивании. Без него, если
> файл с таким именем уже лежит в текущей папке, `wget` не перезапишет
> его, а сохранит рядом как `launcher-trassir-monitor.sh.1` — и
> `bash launcher-trassir-monitor.sh` продолжит молча запускать старую,
> уже скачанную ранее версию, даже после реального обновления на GitHub.
> Тот же принцип касается любого `wget` из этого README — все команды
> ниже уже используют `-O`.

```
TRASSIR-Monitor v13.0

1.  [false] Install Dashboard
2.  [false] Install Email notification
3.  [false] Install Telegram notification

4.  Change admin passwd

5.  Update all
6.  Uninstall

0.  Exit
```

`[true]`/`[false]` в пунктах 1–3 отражают, что уже реально установлено
(проверяется по факту на диске и в systemd, не по отдельному флагу).
Пункт 1 после установки дашборда сразу предлагает поставить Telegram и
Email уведомления — не нужно возвращаться в меню и искать пункты 2/3
отдельно. Пункт 5 обновляет до последней версии с GitHub всё, что уже
установлено, не трогая базу данных, настройки и пароль администратора
(подробности — в разделе про автономную сеть ниже). При первом запуске
лаунчер сам копирует себя в `/usr/local/bin/trassir-monitor` — дальше
меню открывается командой `sudo trassir-monitor` без необходимости
помнить, куда он был скачан.

Ниже — те же самые install-скрипты по отдельности, для тех, кто хочет
устанавливать компоненты вручную, без меню.

### 1. Основной монитор

```bash
wget -O install-trassir-monitor.sh https://raw.githubusercontent.com/scp-oss/TRASSIR-Monitor/main/install-trassir-monitor.sh
bash install-trassir-monitor.sh
```

Установщик спросит:
- **Порт** веб-интерфейса (по умолчанию `8080`)
- **Интервал опроса** серверов в секундах (по умолчанию `15`)
- **Пароль администратора** — нужен для входа и любых изменений (добавление/
  удаление серверов, настройки). Enter вместо пароля — установщик сам
  сгенерирует случайный и покажет его один раз. Сменить позже:
  `sudo trassir-monitor-set-password`.

После установки откройте `http://<IP>:8080` — сам дашборд виден без входа,
но для изменений понадобится пароль, заданный на этом шаге (`/login`).

**Обновление до новой версии** — тот же самый скрипт, запущенный ещё
раз на уже установленной системе: `sudo bash install-trassir-monitor.sh`.
Скрипт сам определяет, что установка уже есть, и ничего не спрашивает —
порт и пароль администратора берутся из уже работающей установки (порт
восстанавливается либо из сохранённых метаданных, либо, если установка
достаточно старая, прямо из действующего конфига nginx — в выводе всегда
видно, откуда именно взято значение). База данных (серверы, история,
алерты) и все настройки сохраняются автоматически, обновляется только
код.

### 3. Email-уведомления *(опционально)* `v1.3`

```bash
wget -O install-mail-notifier.sh https://raw.githubusercontent.com/scp-oss/TRASSIR-Monitor/main/install-mail-notifier.sh
bash install-mail-notifier.sh
```

Потребуется:
- **SMTP-сервер** (например, `smtp.gmail.com`)
- **Порт**: `587` — STARTTLS, `465` — SSL/TLS
- **Логин и пароль** (для Gmail — [пароль приложения App Password](https://myaccount.google.com/apppasswords))
- **Email получателей** — несколько адресов через запятую

> Все параметры можно изменить позже через `/settings` в браузере.

## 🖥 Веб-интерфейс

```
Дашборд:    http://<IP>:8080/
Детали:     http://<IP>:8080/server/<id>
Настройки:  http://<IP>:8080/settings
```

**Дашборд** показывает по каждому серверу: статус · камеры онлайн/всего · CPU · диски · архив · uptime · отклик · счётчик алертов

**Детальная страница** — метрики, интерактивный график, список всех алертов с возможностью сброса (кнопка ✕ у каждого алерта сбрасывает только его, «Сбросить все» — сразу все активные проблемы сервера).

## 🔔 Формат уведомлений

Каждое уведомление (Telegram и Email) содержит:

- 🖥 Название и IP сервера
- ⚠ Описание события (с именами конкретных камер)
- ⏱ Время простоя (для уведомлений о восстановлении)
- 📊 Текущее состояние: CPU%, камеры, архив, uptime, отклик
- 🔗 Прямая ссылка на страницу сервера в мониторе

**Типы алертов:**

| Иконка | Событие |
|---|---|
| ✅ | ВОССТАНОВЛЕНИЕ — камера / сервер вернулся в онлайн + время простоя |
| 📷 | ОТВАЛ КАМЕР — с именами конкретных каналов |
| 🔥 | ВЫСОКАЯ НАГРУЗКА CPU |
| 💾 | ПРОБЛЕМА С АРХИВОМ |
| 💿 | ОШИБКА ДИСКОВ |
| 🔴 | КРИТИЧЕСКИЙ АЛЕРТ |

## 🗑 Удаление

```bash
# Удалить Telegram-бота
sudo bash uninstall-telegram-bot.sh

# Удалить Email-демона
sudo bash uninstall-mail-notifier.sh

# Удалить весь дашборд (Telegram/Email снимаются вместе с ним — без
# дашборда они всё равно не могут работать)
wget -O uninstall-trassir-monitor.sh https://raw.githubusercontent.com/scp-oss/TRASSIR-Monitor/main/uninstall-trassir-monitor.sh
sudo bash uninstall-trassir-monitor.sh

# То же самое, если дашборд уже установлен — короткая команда без wget
sudo trassir-monitor-uninstall
```

Деинсталляторы удаляют **только файлы проекта**. Python, Nginx и системные пакеты сохраняются. База данных сохраняется по запросу.

## 🌐 Готовность к автономной сети (offline / air-gapped)

Дашборд рассчитан на то, чтобы **браузер пользователя не обращался ни к
одному внешнему серверу** — ни к CDN, ни к Google Fonts, ни к чему-либо
ещё за пределами самого сервера мониторинга. Это уже проверено и
работает:

- Bootstrap CSS/JS, Chart.js, Socket.io и иконки (Bootstrap Icons,
  включая шрифты `.woff`/`.woff2`) скачиваются **один раз, во время
  установки**, и кладутся в `/opt/trassir-monitor/static/`. Все
  HTML-шаблоны ссылаются только на `/static/...` — ни одного `<link>`
  или `<script>` с адресом в интернете нигде в дашборде нет.
- Интернет нужен **только на сервере и только в момент самой первой
  установки** — у клиентских браузеров в изолированной сети интернета
  вообще может не быть, дашборду это не мешает.
- Обновление (`launcher-trassir-monitor.sh` → 5, либо повторный запуск
  `install-trassir-monitor.sh`) не перекачивает уже скачанные файлы
  заново и не требует интернета на сервере повторно — они сохраняются и
  восстанавливаются автоматически при каждом обновлении. Если что-то
  всё же не удалось скачать (при самой первой установке без интернета
  либо при обрыве связи посреди неё), установщик прямо и заметно
  предупреждает об этом в конце шага «Создание HTML шаблонов», вместо
  того чтобы молча оставить дашборд без части интерфейса.
- Единственная функция, которой интернет нужен **постоянно, а не
  только при установке** — это сами уведомления в Telegram (обращение к
  `api.telegram.org`) и по email (обращение к SMTP-серверу). Это
  ожидаемо и не противоречит автономности дашборда: если в сети совсем
  нет интернета, эти уведомления просто не смогут доставляться, но сам
  дашборд, история, алерты и веб-интерфейс продолжат работать без
  единого обращения наружу.

## ❓ Частые вопросы

**Почему имена камер не видны сразу?**  
Имена запрашиваются только при наличии офлайн-камер. Для большого количества каналов запрос идёт последовательно и занимает несколько секунд.

**Как изменить порт после установки?**  
Отредактируйте `/etc/nginx/sites-available/trassir-monitor`, замените `listen <порт>`, затем `systemctl reload nginx`.

**Можно ли без SSL?**  
Да — при добавлении сервера снимите галочку «Использовать SSL».

**Gmail не отправляет письма?**  
Нужен [пароль приложения (App Password)](https://myaccount.google.com/apppasswords), не основной пароль аккаунта.

## 🔐 Безопасность / Авторизация

Дашборд (`/`, `/server/<id>`) виден всем без входа — это осознанный дизайн для
экрана в общем доступе. Но **любое изменение** — добавление/редактирование/
удаление сервера, изменение настроек мониторинга, SMTP, Telegram, смена
пароля, сброс алертов — требует входа на `/login`.

- **Пароль администратора задаётся прямо в установочном скрипте** —
  `install-trassir-monitor.sh` спросит его на шаге настройки (можно нажать
  Enter, чтобы сгенерировать случайный 16-символьный пароль — он будет
  показан один раз, сразу после генерации, второй раз нигде не всплывёт).
  Никакого захардкоженного пароля по умолчанию в системе не остаётся.
- **Сменить пароль позже, без входа в веб-интерфейс:**
  ```bash
  sudo trassir-monitor-set-password
  ```
  Пишет новый хеш напрямую в БД — полезно, если пароль забыт и войти на
  `/settings`, чтобы сменить его там, уже нельзя. Также доступно из
  веб-интерфейса: `/settings` → «Сменить пароль».
- Пароль хранится в БД в виде хеша (werkzeug `pbkdf2`/`scrypt`), не открытым
  текстом.
- После 5 неудачных попыток входа с одного IP — блокировка на 5 минут.
- Секретный ключ сессии сохраняется в `data/secret_key.txt` (права `600`) и
  переживает `systemctl restart` — сессии не сбрасываются на каждом
  перезапуске сервиса.
- SDK-пароли серверов TRASSIR никогда не отдаются обратно через `/api/servers`
  или веб-интерфейс — только `has_password: true/false`. При редактировании
  сервера пустое поле пароля означает «оставить как есть».
